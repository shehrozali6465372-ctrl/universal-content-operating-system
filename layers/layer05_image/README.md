**Status:** 🟡 Hardened — Not Production Certified

## Description

Layer 5 owns image planning, prompt construction, provider orchestration, real generation, persistence, optimization, memory, and provenance.

## Real Provider Boundary

- **Puter.js:** primary production smoke provider through the official Node.js `@heyputer/puter.js` SDK.
- Backend/CI Puter execution requires `PUTER_AUTH_TOKEN`; provider API keys are not accepted as a substitute.
- The production boundary rejects `test_mode=true` so synthetic/sample images cannot be certified.
- Generated bytes are validated for nonempty content, supported image signatures, image MIME type, and SHA-256 provenance.
- Persistence is atomic and uses the full SHA-256 digest as the artifact filename.
- Puter hosted URLs are treated as transient; the provider materializes the returned bytes locally before downstream use.

## Certification Gates

Layer 5 remains **Not Production Certified** until all required evidence passes:

1. Python/unit/contract tests.
2. Real Puter generation with a configured `PUTER_AUTH_TOKEN`.
3. Real nonempty image bytes.
4. Persisted bytes exactly match returned bytes.
5. SHA-256 metadata exactly matches persisted/returned bytes.
6. Auth, timeout, malformed response, empty response, non-image response, storage, and runtime failure paths.
7. Cross-layer Layer 4 → Layer 5 → downstream E2E.
8. Concurrency/idempotency and duplicate/orphan cleanup checks.
9. Full UCOS 23-layer boot and final production certification workflow.

A documentation-only check, mock response, or `test_mode` result is not certification evidence.

## Current Blocker

The latest code now requires the GitHub Actions secret `PUTER_AUTH_TOKEN` and a successful real Puter smoke. The GitHub connector currently exposes no completed workflow run/status for the latest certification commits, so production certification is intentionally still blocked.
